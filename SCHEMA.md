# Schema - `data/municipalities.json`

Single JSON file, regenerated by `scraper/scrape.js` and committed by CI.

```json
{
  "schema_version": 2,
  "generated_at": "2026-09-11T00:00:00Z",
  "source_url": "https://ij.org/institute-for-justice-unveils-new-database-tracking-cancelations-of-license-plate-reader-contracts/",
  "source_name": "Institute for Justice - ALPR Camera Contract Cancelations",
  "count": 0,
  "entries": [ /* Entry, see below */ ]
}
```

## Top-level fields

| Field | Type | Notes |
|---|---|---|
| `schema_version` | integer | Bump on breaking changes to the `Entry` shape. `2` marks the switch from deflock.org to IJ's database - ids are not stable across that boundary. |
| `generated_at` | ISO 8601 string | Timestamp of the run that produced this file. Only advances when the run also produces a substantive change - see "No-op runs" below. |
| `source_url` | string | The page this data is sourced from. |
| `source_name` | string | Human-readable name of the source. |
| `count` | integer | `entries.length`, for convenience. |
| `entries` | Entry[] | See below. |

## Entry

| Field | Type | Notes |
|---|---|---|
| `id` | string | Stable slug: `slugify(city + state) + "-" + YYYY-MM`. Does **not** change across rescrapes of the same underlying row. Collisions (same city/state/month) are disambiguated with a `-2`, `-3`, ... suffix assigned by ascending `ij_source_id`, so a new colliding row never displaces an existing id. |
| `ij_source_id` | string | IJ's own internal incident id (their `data-alpr-incident` attribute) for this row. The authoritative external identity - used to detect rows disappearing from the source, independent of `id`. |
| `source_order` | integer | Position in source's display order (newest first). Reference only, never used as identity. |
| `location.city` | string | |
| `location.state` | string | Two-letter USPS code, resolved from the source's full state name. |
| `location.text` | string | `"City, ST"`. |
| `date.text` | string | `"Month YYYY"`, derived from `date.iso`. |
| `date.year` / `date.month` | integer | |
| `date.iso` | string | `YYYY-MM-DD`, day precision as given by the source. |
| `status` | enum | Normalized from the source's outcome categories: `cancelation_before_deployment` \| `early_termination` \| `nonrenewal_after_expiration` \| `nonrenewal_defunding` \| `other`. `other` covers any future category the source adds that isn't mapped yet - check `status_raw`. |
| `status_raw` | string | Exact outcome text from the source (e.g. `"Early termination"`). |
| `manufacturer` | string \| null | ALPR vendor slug as given by the source (e.g. `"flock"`). Not filtered - this dataset keeps all vendors IJ tracks, same approach as `flock-misuse-tracker`. |
| `manufacturer_name` | string \| null | Human-readable vendor name (e.g. `"Flock"`). |
| `info` | string | Plain-text description of the cancelation, as given by the source. |
| `source_url` | string | The source's own "Original source" article link for this row. |
| `link_domain` | string | Hostname of `source_url`, `www.` stripped. |
| `archive_url` | string \| null | Wayback Machine snapshot of `source_url`, via the [Save API](https://web.archive.org/save/). `null` if a snapshot couldn't be confirmed yet (retried on the next run). |
| `article_excerpt` | string \| null | Short (1–3 sentence, ≤400 char) excerpt only. **Never the full article text** - full text is not fetched to disk or published, to avoid copyright exposure. Pulled from the article's meta description/og:description when available, otherwise the first substantial paragraph. |
| `article_fetch.fetched_at` | ISO 8601 string | When the article was last fetched. |
| `article_fetch.status` | enum | `ok` \| `paywalled` \| `404` \| `blocked`. `blocked` covers network errors, timeouts, and non-404 error responses (403, 5xx, etc). |
| `first_seen_at` | ISO 8601 string | When this row (by `id`) was first scraped. Never changes after that. |
| `last_seen_at` | ISO 8601 string | Last time this row was present in the source during a run that produced a commit. (Doesn't advance on no-op runs - see below.) |
| `content_hash` | string | `sha256:<hex>` over `{location, date:{year,month,iso}, status_raw, manufacturer, info, source_url}`. Used to detect real changes vs. no-op rescrapes, and to decide whether to re-fetch the article/re-archive. |
| `verified` | boolean | Manual curator flag for human QA, independent of the scrape. Defaults `false`, preserved across rescrapes. |
| `notes` | string | Free-text curator notes. Preserved across rescrapes. |
| `flagged_missing` | boolean | Present and `true` only when this row's `id` disappeared from the source table. Rows are never silently dropped. |
| `missing_since` | ISO 8601 string | Present only alongside `flagged_missing`. First run where the row was no longer found in the source. |

## No-op runs

The scraper always writes fresh `generated_at`/`last_seen_at` values when it runs. CI (`scraper/checkSubstantiveChange.js`) compares the new output against the last committed version with those two volatile fields stripped out; if nothing else differs, the working-tree write is discarded and no commit is made. This keeps daily runs from producing noise commits while still being safe to run unconditionally.

## Article fetch and archival

- Articles are only (re-)fetched when a row is new, its `content_hash` changed, or the last fetch was `blocked`.
- Archival uses the Wayback Machine Save API (`https://web.archive.org/save/<url>`); the resulting `Content-Location` becomes `archive_url`.
- The Save API rate-limits bursts hard and can be slow even on success, so archiving runs serially, paced, and bounded by a hard wall-clock time budget per run (not a request count - individual retries make duration unpredictable). Rows still missing `archive_url` when the budget runs out are picked up on the next scheduled run - a large backlog fills in gradually rather than all at once.
